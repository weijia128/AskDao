# AskDao 微信小程序上线准备流程

## 1. 你需要先决定的事项

### 主体类型

需要先决定小程序注册主体：

- 个人主体。
- 个体工商户主体。
- 企业主体。

建议：

- 如果只是非常早期验证，可以评估个人主体是否满足当前类目和能力。
- 如果后续要做支付、商业化、品牌化运营，企业或个体工商户主体更稳。
- 主体类型会影响认证、类目、支付、备案和部分开放能力，注册前要先确认。

### 产品名称

候选：

- 问道。
- AskDao。
- 问道 AskDao。

建议国内小程序优先使用中文品牌「问道」，英文 AskDao 可作为 Logo 或副标题露出。

### 服务类目

首版定位建议围绕：

- 传统文化体验。
- 生活服务 / 工具。
- 娱乐参考。
- 心理自省。

类目选择要避开强「算命、预测、改命、转运」表达，具体以微信公众平台后台可选类目为准。

## 2. 账号注册准备

准备资料：

- 未注册过公众平台、开放平台、企业号、个人号绑定的邮箱。
- 管理员微信号。
- 管理员手机号。
- 管理员身份证实名信息。
- 小程序名称。
- 小程序头像。
- 小程序简介。
- 服务类目。

如果使用个体工商户或企业主体，还需要：

- 营业执照。
- 统一社会信用代码。
- 法人或经营者信息。
- 对公账户或微信认证所需材料。
- 主体联系人信息。

注册入口：

- 微信公众平台：https://mp.weixin.qq.com/

## 3. 备案准备

国内小程序上线前需要考虑备案。工信部移动互联网应用程序备案要求覆盖 App，也包括小程序、快应用等分发形态。

准备资料通常包括：

- 主办单位证件。
- 主体负责人证件。
- 小程序负责人证件。
- 负责人手机号。
- 负责人邮箱。
- 联系地址。
- 小程序名称。
- 小程序图标。
- 小程序服务内容说明。
- 真实性核验材料。
- 承诺书或平台要求的其他材料。

如涉及新闻、出版、教育、医疗、药品、宗教、金融等特殊服务，可能需要前置审批文件。AskDao 首版应避免进入这些高风险服务范围。

参考入口：

- 工信部移动互联网应用程序备案通知：https://www.gov.cn/zhengce/zhengceku/202308/content_6897341.htm?type=mobile-internet
- 工信部备案系统：https://beian.miit.gov.cn/

## 4. 开发环境准备

需要安装：

- 微信开发者工具。
- Node.js。
- Git。
- 代码编辑器，例如 VS Code。

需要拿到：

- 小程序 AppID。
- 管理员或开发者权限。
- GitHub 仓库权限。

开发入口：

- 微信开发者工具：https://developers.weixin.qq.com/miniprogram/dev/devtools/devtools.html
- 小程序开发文档：https://developers.weixin.qq.com/miniprogram/dev/framework/

## 5. 后端与域名准备

如果首版只做规则层 + 模板解读，可以先不准备复杂后端。

如果要接大模型、生成带参数小程序码、保存云端记录，则需要：

- 后端服务或云函数。
- 已备案域名。
- HTTPS 证书。
- 小程序后台配置合法服务器域名。
- 服务端保存大模型 API Key。
- 基础日志和错误监控。

注意：

- 大模型 API Key 不能放在小程序前端。
- 小程序请求外部接口通常需要配置合法域名。
- 如果使用云开发，也要确认云环境、权限和费用。

参考入口：

- 小程序网络能力与域名配置：https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html

## 6. 隐私与权限准备

AskDao 首版预计至少使用：

- 保存图片到相册。
- 本地保存最近记录。

如果后续增加登录、云记录或用户画像，还可能涉及：

- 用户标识。
- 用户输入的问题。
- 使用记录。
- 分享来源参数。

需要准备：

- 用户隐私保护指引。
- 保存相册用途说明。
- 用户输入问题的处理说明。
- 数据保存周期说明。
- 删除或清除本地记录入口。

产品原则：

- 默认不在分享卡片展示用户原问题。
- 首版不收集生辰八字、人脸、手相、证件号等高敏信息。
- 高风险问题只做提示，不给具体决策建议。

### 用户隐私保护指引填写文案（可直接粘贴）

在公众平台「设置 → 服务内容声明 → 用户隐私保护指引」中按以下要点填写：

- **收集的个人信息类型**：本小程序不收集任何个人信息。不获取微信昵称、头像、手机号、位置信息，不要求登录。
- **相册（仅写入）权限**：用于将您生成的断课结果卡片图片保存到系统相册。本小程序不会读取您相册中的任何内容。
- **本地存储说明**：您的问道记录与「此念」笔记仅保存在您本机的微信存储中，不会上传到任何服务器。您可以在「问道记录」页左滑删除单条记录，或使用「清除全部记录」一键清空全部本地数据。
- **第三方 SDK**：仅使用 lunar-javascript 本地历法计算库，所有计算在设备本地完成，无任何数据外发。

参考入口：

- 用户隐私保护指引：https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/
- 保存图片到相册 API：https://developers.weixin.qq.com/miniprogram/dev/api/media/image/wx.saveImageToPhotosAlbum.html

## 7. 内容与审核准备

需要提前准备：

- 小程序名称。
- 小程序头像。
- 小程序简介。
- 首页截图。
- 小六壬流程截图。
- 金钱卦流程截图。
- 结果页截图。
- 分享卡片截图。
- 服务类目说明。
- 免责声明。

文案边界：

- 使用「传统文化体验」「自我参考」「签语」「问道」「观心」。
- 避免「预测未来」「必中」「改命」「转运」「化解灾祸」「付费消灾」。
- 不制造焦虑，不恐吓用户。
- 不诱导分享。

建议免责声明：

```text
仅供传统文化体验与自我参考。
```

## 8. 发布前测试清单

### 功能测试

- 首页能正常进入。
- 小六壬能按当前时间计算。
- 小六壬固定样例结果正确。
- 金钱卦六次掷钱流程完整。
- 结果页展示完整。
- 保存卡片到相册可用。
- 分享入口可用。
- 最近记录可保存和清除。

### 规则测试

- 农历转换正确。
- 子时边界正确。
- 辰时序号为 5。
- 小六壬公式结果正确。
- 六象到阻 / 平 / 顺映射正确。

### 审核测试

- 页面没有绝对预测。
- 页面没有诱导付费。
- 页面没有恐吓用户。
- 页面没有收集高敏信息。
- 隐私说明覆盖已使用权限。

## 9. 建议时间线

### 第 1 步：资料准备

- 确认主体类型。
- 确认小程序名称。
- 准备头像、简介、类目。
- 注册小程序账号。

### 第 2 步：研发试跑

- 创建小程序项目。
- 实现小六壬规则。
- 实现首页、结果页、分享卡片。
- 在开发者工具内预览。

### 第 3 步：备案与后台配置

- 提交备案资料。
- 配置隐私保护指引。
- 配置必要权限说明。
- 如有后端，配置合法域名。

### 第 4 步：内部测试

- 管理员和体验成员测试。
- 测试保存卡片和分享路径。
- 修正文案和视觉问题。

### 第 5 步：提交审核

- 上传代码。
- 填写版本说明。
- 提交审核。
- 根据审核反馈调整。

### 第 6 步：灰度试水

- 先在小范围群聊和朋友圈测试。
- 观察访问、起问完成、保存卡片、分享和留存。
- 决定是否加入大模型解读层。

## 10. 你现在可以先准备的清单

- 注册主体类型。
- 小程序名称和备用名称。
- 小程序头像。
- 小程序简介，建议 20-40 字。
- 首页标语。
- 小六壬和金钱卦卡片文案。
- 结果卡片视觉方向。
- 管理员微信号和邮箱。
- 如用企业或个体主体，准备营业执照和负责人信息。
- 如后续接大模型，准备后端部署和域名方案。

## 11. 当前建议

AskDao 当前阶段建议先走：

```text
原生微信小程序
→ 个人或轻主体试水
→ 规则层 + 模板文案
→ 保存分享卡片
→ 小范围传播验证
→ 再接大模型和后端
```

不要一开始把注册、备案、后端、大模型、支付、会员、App 全部压进第一版。第一版只要把问道服务和分享闭环打磨好。
