# AskDao 微信小程序试水版 MVP PRD

## 1. 背景与策略调整

AskDao 原始方向是面向海外用户的传统文化 AI App。当前阶段调整为先做国内微信小程序试水，不优先做原生 App，也暂不考虑付费。

试水阶段重点不是验证「能不能算」，而是验证：

- 用户是否愿意完成一次轻量问道流程。
- 用户是否愿意保存并分享结果卡片。
- 分享是否能带来新用户进入。

小程序 MVP 0.1 只做小六壬单玩法闭环。金钱卦、AI 解读、用户体系和后端服务后移。

## 2. 产品定位

问道是一款偏神秘仪式感的轻量微信小程序。用户每天打开后，可以获得一个今日启发，并通过小六壬对当下困惑获得一个含蓄回应。

产品不强调预测准确性，不承诺结果，不引导用户依赖占断。核心价值是：

- 给用户一个安顿情绪的仪式。
- 给问题一个新的观察角度。
- 给行动一个温和提醒。
- 给微信传播一个好看的分享卡片。

一句话定位：

> 一个有东方仪式感的轻量自我观察工具。

## 3. 目标用户

### 核心用户

- 年龄：20-40 岁。
- 场景：遇到选择、关系、事业、状态问题时，希望获得一个带仪式感的回应。
- 兴趣：传统文化、玄学内容、塔罗、星座、心理测试、情绪疗愈、生活方式内容。
- 使用习惯：愿意在微信群、朋友圈、小红书等场景分享结果图。

### 暂不服务

- 专业命理用户。
- 期待精确断事、改命、转运的人。
- 需要医疗、法律、金融、投资建议的人。
- 想通过平台获得真人咨询的人。

## 4. MVP 核心假设

| 假设 | 内容 | 验证指标 |
|---|---|---|
| H1 | 用户愿意完成一次轻量问道流程 | 起问开始率、起问完成率 |
| H2 | 用户愿意保存或分享结果卡片 | 保存卡片率、分享点击率 |
| H3 | 分享能带来新用户进入 | 分享回流人数、回流用户起问率 |
| H4 | 每日仪式能提升再次打开 | 次日留存、7 日留存 |

## 5. MVP 0.1 目标

首版不验证付费，不验证 AI，不验证多术法，优先验证传播与留存。

核心指标：

- 访问人数。
- 起问开始率。
- 起问完成率。
- 结果页到达率。
- 保存卡片率。
- 分享点击率。
- 分享回流人数。
- 回流用户起问率。
- 次日留存。
- 7 日留存。

阶段性成功信号：

- 用户打开后能在 1 分钟内完成一次问道。
- 结果卡片足够有保存或转发欲。
- 新用户从分享卡片进入后能快速理解并开始使用。
- 用户愿意因为「今日问道」再次打开。

## 6. MVP 0.1 功能范围

### 必做

1. **今日问道首页**
   - 首页第一屏不再是算法入口，而是每日仪式入口。
   - 顶部展示占前提示：

```text
不诚不占，不疑不占，不义不占
```

   - 首页核心结构：

```text
今日问道

今日之象：大安
今日提醒：宜稳中求进，不宜急躁。
今日一问：今天有什么事情值得重新观察？

[开始问道]
```

   - 下方展示「快速问事：小六壬」。

2. **心中默问起念**
   - 用户开始问道后，不要求选择问题类型，也不要求填写问题。
   - 页面提示用户静心一念、心中默问。
   - 提醒用户问一件小事、一个方向。
   - 示例：宜问「这件事今天推进，是否合适？」；不宜问「我应该怎么办？」。
   - 提醒用户不以玩笑试探，不反复追问同一事。
   - 系统以用户点击确认时的本地时间作为起念时间。
   - 问事方向和文字输入后续可作为可选增强，不进入 MVP 0.1 主流程。
   - 每日最多三问，超过后提示明日再来。

3. **小六壬**
   - 卡片小字：

```text
遇事不决，六壬决断
```

   - 按用户起念时间推算，取农历月、农历日和时辰。
   - 首版采用用户设备当前本地时间，不要求用户手动选择时间。
   - 首版结果主展示只输出三档：
     - 阻
     - 平
     - 顺
   - 结果页可用小字展示六象，例如「小六壬：大安」。

4. **结果页**
   - 结果不使用绝对预测语言。
   - 核心结构：
     - 结果档位：阻 / 平 / 顺。
     - 六象：大安 / 留连 / 速喜 / 赤口 / 小吉 / 空亡。
     - 一句签语。
     - 一段解释。
     - 一个行动提醒。
     - 一个反思问题。
   - 默认不展示用户原问题，保护隐私。

5. **保存分享卡片**
   - 生成适合朋友圈的竖版结果卡片。
   - 卡片内容包括：
     - 产品名：问道 / AskDao。
     - 卡片模板 ID。
     - 结果档位：阻 / 平 / 顺。
     - 六象。
     - 签语。
     - 简短行动提醒。
     - 小程序码。
   - 用户可保存到相册，再发朋友圈或群聊。

6. **本地历史**
   - 本地保存最近问道记录。
   - 首版不强制登录，不做云同步。
   - 历史记录保存结构化结果，不把用户原问题放入分享卡片。

7. **基础埋点**
   - 记录关键转化漏斗事件。
   - 首版只需要能分析访问、起问、完成、保存、分享和回流。

8. **轻量风险过滤**
   - MVP 0.1 主流程不采集问题文本，因此不做强制输入风险过滤。
   - 如果后续开放可选文字输入，再启用关键词风险检测。
   - 首版不做复杂 AI 审核。

### 暂不做

- 金钱卦。
- AI / 大模型解读。
- 后端服务。
- 用户账号体系。
- 付费、订阅、点数包。
- 真人咨询。
- 八字、紫微斗数、风水罗盘、复杂命盘。
- 社区、评论、好友关系。
- 广告变现。
- 复杂历史记录云同步。
- 医疗、法律、金融、投资等问题的具体建议。

## 7. 核心用户路径

### 路径 A：每日问道

1. 用户打开小程序。
2. 看到今日问道：今日之象、今日提醒、今日一问。
3. 点击「开始问道」。
4. 进入起念页，心中默问。
5. 系统按起念时间计算小六壬。
6. 用户看到「阻 / 平 / 顺」、六象、签语和行动提醒。
7. 用户保存分享卡片。
8. 好友扫码或点击分享进入小程序。
9. 回流用户进入同样的今日问道流程。

### 路径 B：快速问事

1. 用户从首页点击「小六壬」。
2. 进入起念页，心中默问。
3. 完成轻量起念动画。
4. 查看结果页。
5. 保存结果卡片或查看最近记录。

## 8. 问题输入策略

MVP 0.1 不要求用户输入问题，也不要求选择问题分类。小六壬按起念时间计算，默认问题方向为 `daily_state`，用于兼容现有模板和埋点字段。

后续如果恢复可选问题输入，它的目的不是影响规则计算，而是：

- 给解读文案提供场景。
- 降低开放式输入的认知落差。
- 统计用户真实需求。
- 降低医疗、金融、死亡、自伤等高风险问题。

后续可选输入结构：

```json
{
  "question_type": "work_choice",
  "question_text": "是否应该换一个方向",
  "is_optional_text": true
}
```

问题类型映射：

| 展示文案 | 字段值 |
|---|---|
| 今天状态 | daily_state |
| 工作选择 | work_choice |
| 人际关系 | interpersonal |
| 感情关系 | relationship |
| 一个决定 | decision |
| 随便问问 | open |

## 9. 小六壬计算规则

小六壬按起念时间计算，输入为：

- 农历月份。
- 农历日期。
- 时辰序号。

公式为：

```text
小六壬序号 = (农历月 + 农历日 + 时辰序号 - 2) % 6
```

余数映射规则：

| 余数 | 六象 |
|---|---|
| 1 | 大安 |
| 2 | 留连 |
| 3 | 速喜 |
| 4 | 赤口 |
| 5 | 小吉 |
| 0 | 空亡 |

注意：如果用户使用的是手机当前公历时间，系统需要先将公历日期转换为农历月日，再代入公式。

时辰序号：

| 时辰 | 时间段 | 序号 |
|---|---|---|
| 子 | 23:00-00:59 | 1 |
| 丑 | 01:00-02:59 | 2 |
| 寅 | 03:00-04:59 | 3 |
| 卯 | 05:00-06:59 | 4 |
| 辰 | 07:00-08:59 | 5 |
| 巳 | 09:00-10:59 | 6 |
| 午 | 11:00-12:59 | 7 |
| 未 | 13:00-14:59 | 8 |
| 申 | 15:00-16:59 | 9 |
| 酉 | 17:00-18:59 | 10 |
| 戌 | 19:00-20:59 | 11 |
| 亥 | 21:00-22:59 | 12 |

示例：

```text
农历七月二十一日上午 7 点，为辰时。
农历月 7，农历日 21，辰时序号 5。
公式为：(7 + 21 + 5 - 2) % 6 = 1。
最终六象落「大安」。
```

## 10. 小六壬三档映射

小六壬内部保留六象，用户主结果收束为三档。

| 六象 | 主结果 | 表达方向 |
|---|---|---|
| 大安 | 顺 | 稳定、可守、可小步推进 |
| 留连 | 平 | 迟滞、拖延、宜再观察 |
| 速喜 | 顺 | 有消息、有转机、宜顺势推进 |
| 赤口 | 阻 | 口舌、冲突、宜谨慎沟通 |
| 小吉 | 顺 | 小有助力、可试探推进 |
| 空亡 | 阻 | 落空、不实、宜暂缓 |

三档结果：

| 档位 | 含义 | 表达方向 |
|---|---|---|
| 阻 | 此事有滞，宜缓不宜急 | 提醒暂停、观察、避险 |
| 平 | 势在中途，需再观察 | 提醒等待、确认、蓄力 |
| 顺 | 气机渐开，可小步推进 | 提醒行动、推进、把握时机 |

## 11. 文案原则

允许使用：

- 气机。
- 时势。
- 阴阳。
- 象。
- 宜缓。
- 可进。
- 自省。
- 观心。
- 签语。

避免使用：

- 必中。
- 必然。
- 保证。
- 改命。
- 转运。
- 预测结局。
- 今日必发。
- 破解灾祸。
- 付费化解。

结果页底部固定提示：

```text
仅供传统文化体验与自我参考。
```

## 12. 分享卡片设计要求

分享卡片是 MVP 0.1 传播验证的核心，不是附属功能。

### 内容要求

- 不展示用户原问题。
- 不展示过长解释。
- 不制造焦虑。
- 重点呈现签语和结果氛围。
- 明确展示小程序码，方便回流。

### 模板预留

首版不实现复杂 A/B 测试平台，但分享卡片数据结构必须预留 `template_id`。

建议先准备三类模板：

| 模板 | 类型 | 示例 |
|---|---|---|
| A01 | 结果型 | 今日问道 / 大安 / 宜稳而行 |
| B01 | 人格型 | 你的今日之象：大安 / 你正在进入适合沉淀的阶段 |
| C01 | 问题型 | 今日一问：你的答案是什么？扫码一起问道 |

首版可以先上线 A01，后续根据保存率和回流率扩展 B01 / C01。

### 建议版式

- 顶部：问道 / AskDao。
- 中部：结果档位大字，例如「顺」。
- 中下：签语。
- 底部：行动提醒、小程序码。

### 视觉方向

- 玄黑。
- 宣纸白。
- 朱砂红。
- 暗金铜钱。
- 轻微烛光、粒子或铜钱落定动效。

视觉要有东方神秘感，但保持克制，不做廉价恐吓或夸张营销风。

## 13. 留存机制

首页留存要靠「每日仪式」，不是靠复杂任务。

首版可做：

- 今日之象。
- 今日提醒。
- 今日一问。
- 每日最多三问。
- 最近问道记录本地保存。
- 收藏有启发的结果。

今日内容可以先由日期和小六壬结果映射预设文案生成，不依赖大模型。

## 14. 数据埋点设计

首版必须能分析完整漏斗。

| 事件 | 触发时机 | 关键属性 |
|---|---|---|
| page_view | 进入页面 | page, source, scene |
| view_daily_ritual | 看到今日问道模块 | daily_symbol, daily_grade |
| click_start | 点击开始问道 | entry: daily / quick |
| start_divination | 开始小六壬推算 | method |
| complete_divination | 规则计算完成 | symbol, grade, rule_version |
| view_result | 查看结果页 | symbol, grade |
| save_poster | 保存分享卡片 | template_id, symbol, grade |
| share_click | 点击分享入口 | template_id, channel |
| reopen_from_share | 从分享回流 | template_id, share_scene |
| view_history | 查看历史记录 | count |

## 15. 合规与内容边界

产品必须保持传统文化体验、自省启发、娱乐参考定位。

不做：

- 明示或暗示准确预测未来。
- 对医疗、法律、金融、投资问题给具体建议。
- 恐吓用户。
- 诱导付费化解。
- 收集生辰八字、人脸、手相、证件号等高敏信息。
- 诱导分享。

### 输入风险检测

首版采用关键词规则，不做复杂 AI 审核。

示例风险词：

| 类型 | 示例关键词 |
|---|---|
| medical | 癌、疾病、症状、诊断、吃药、手术 |
| finance | 股票、彩票、投资、借钱、贷款、暴富 |
| life | 死亡、自杀、自残、活不下去 |
| legal | 违法、坐牢、起诉、判刑 |

命中后提示：

```text
问道仅作为传统文化体验和自我参考。
涉及健康、法律、财务或人身安全的问题，请咨询专业人士或及时寻求现实帮助。
```

对高风险问题，应引导用户改成适合自我观察的问题，例如「我现在可以先做哪一步」。

## 16. 首版架构原则

首版采用分层架构，不引入智能体，不接大模型，不做后端强依赖。

### 规则层

规则层负责小六壬计算，只输出结构化结果。

规则层要求：

- 计算过程确定，不依赖大模型。
- 同一输入必须得到同一结果。
- 结果可通过单元测试验证。
- 输出结构化字段，供结果页、分享卡片和解读层复用。
- 规则结果包含 `rule_version`、`input_snapshot`、`calculation`、`symbol`、`grade`、`created_at`。

### 解读层

MVP 0.1 使用模板解读，不接大模型。

解读层要求：

- 只基于规则层结果和默认场景生成文案。
- 后续接入问事方向或可选输入时，可再扩展上下文。
- 不重新计算小六壬。
- 不改变 `symbol` 和 `grade`。
- 不输出绝对预测、保证性判断或高风险建议。
- 输出长度适合结果页和分享卡片二次裁剪。

### 编排层

编排层由小程序页面流程承担，负责控制用户从首页、起念页、结果页到保存分享卡片的路径。

首版编排层要求：

- 用户点击「开始问道」后直接进入起念页。
- 用户确认后，按当前时间调用小六壬规则层。
- 规则层完成后，调用模板解读层生成文案。
- 分享卡片优先使用规则层结构化结果和短签语。

## 17. 版本路线

### MVP 0.1：传播闭环

目标：验证是否有人愿意用和传播。

包含：

- 小六壬。
- 今日问道。
- 心中默问起念。
- 结果页。
- 分享卡片。
- 本地历史。
- 基础埋点。
- 风险过滤接口预留。

不包含：

- 金钱卦。
- AI。
- 用户系统。
- 后端。

### V1.0：内容质量

目标：提升结果解释质量和玩法丰富度。

增加：

- 金钱卦。
- LLM 解读。
- 内容安全审核。
- Prompt 管理。
- 分享模板扩展。

### V2：产品化

目标：从传播型小程序转向可持续产品。

增加：

- 用户体系。
- 云历史。
- 个性化。
- AI 交互。
- App 版本评估。
